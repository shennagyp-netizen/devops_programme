# Curriculum Specification

## Programme levels

The five-day material is retained as the initial intermediate operational core. The programme now exposes three distinct courses:

### Beginner
DevOps through problems:
Linux/networking -> protocols -> containers -> orchestration -> CI/CD -> infrastructure -> reliability, introduced as solutions to real system problems.

### Intermediate
Full DevOps engineering:
deep Linux/networking, Docker, Kubernetes, CI/CD, Terraform/cloud, observability, distributed systems, reliability and incident response.

### Advanced
Large-scale distributed systems:
capacity, global traffic, partitioning, data locality, partial failure, resilience, multi-region systems, disaster recovery and incident engineering.

## Foundations

Reusable foundation domains:
- Linux
- operating systems
- networking
- protocols
- databases
- distributed systems
- reliability

Foundations are independently addressable and are also activated in-context by application sections.

## Section contract

Every section has:
- stable ID
- title
- objective
- foundation dependencies
- teaching assets
- mandatory exercise
- deliberate failure
- project connection
- retrieval
- production design
- conceptual assessment
- diagnostic assessment
- hands-on assessment

## Assessment rule

Each of the three assessment families is a controlled form with varied difficulty. The form generator must preserve competency coverage, expected time, task type and difficulty profile across equivalent forms.

## Existing intermediate core

Day 1: Linux + networking foundations.
Day 2: networking protocols + Docker.
Day 3: Kubernetes.
Day 4: CI/CD + Terraform + cloud.
Day 5: scale + distributed systems + SRE + incident response.

Stable lesson contract remains:
`id, title, domain, objective, lab, failure mode, recall, design connection, podcast path`.
