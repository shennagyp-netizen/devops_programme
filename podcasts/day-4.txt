EPISODE D4.1 — Git as a Production Workflow

Speaker A: We build an operational mental model, not a vocabulary list.

Speaker B: I understand application development. What changes when I operate the system?

Speaker A: CI/CD turns source change into a deterministic process. Separate source, tests, artifact, promotion, deployment and rollback so production does not depend on a workstation.

Speaker B: Give me the failure-oriented version.

Speaker A: State the normal causal path. Then ask what evidence appears when each dependency fails. Identify the layer, inputs, outputs, and next dependency.

Hands-on: Use the Mac to perform an experiment related to Git as a Production Workflow. Predict the result before running it, execute it, capture the evidence, and explain the difference between hypothesis and reality.

Production: Place Git as a Production Workflow in a system serving millions of users. Identify dependencies, failure domain, first useful signal, mitigation, recovery, and what automation should do before a human intervenes.

Recall: 1) explain without notes; 2) draw the causal flow; 3) give two failure modes and their symptoms; 4) name the first diagnostic evidence; 5) explain how scale changes the problem.
