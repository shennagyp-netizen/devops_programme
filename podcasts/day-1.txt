EPISODE D1.5 — IP Addresses, Subnets and CIDR

Speaker A: CIDR stops being mysterious when you treat it as a boundary.

Speaker B: The slash tells me how much of the address belongs to the network.

Speaker A: Exactly.

Speaker B: So the picture is Address -> Prefix -> Boundary -> Range -> Verify.

Speaker A: Good. For IPv4, there are thirty-two address bits. The prefix length tells us how many leading bits define the network portion.

Speaker B: The remaining bits are host space.

Speaker A: Right.

Speaker B: Prediction.

Speaker A: A /24 has more addresses in each block than a /26. True?

Speaker B: True. /26 uses more bits for the network, leaving fewer host bits.

Speaker A: Good.

Speaker B: So subnetting is really about changing the boundary.

Speaker A: Exactly.

Speaker B: Take 192.168.1.0/24.

Speaker A: Twenty-four network bits. Eight host bits.

Speaker B: Two to the eight gives 256 addresses in the block.

Speaker A: Correct.

Speaker B: Now /26.

Speaker A: Six host bits.

Speaker B: Two to the six gives 64 addresses per block.

Speaker A: Exactly.

Speaker B: So the /24 can be divided into four /26 blocks.

Speaker A: Good.

Speaker B: And the boundaries are .0, .64, .128 and .192.

Speaker A: Exactly.

Speaker B: That means 192.168.1.130/26 belongs to the .128 block.

Speaker A: Correct.

Speaker B: This is easier than memorizing subnet-mask tables.

Speaker A: That is the goal. Derive the answer.

Speaker B: So what is the failure mode?

Speaker A: Picking an arbitrary endpoint that is not aligned with the prefix.

Speaker B: Example: saying a /26 block starts at .64 and ends at .100.

Speaker A: Exactly. The block size says where the next boundary must occur.

Speaker B: So the prefix constrains the possible ranges.

Speaker A: Yes.

Speaker B: What about network and broadcast addresses?

Speaker A: In ordinary IPv4 subnetting, those addresses have traditional special meanings, so the usual host-range calculation excludes them. But do not treat that as a universal law for every addressing design or protocol.

Speaker B: So I keep the model, but I keep the context too.

Speaker A: Exactly.

Speaker B: Now why does segmentation matter to an engineer?

Speaker A: Because a subnet is not only an address bucket. It can help define routing boundaries, security boundaries, fault domains and clearer ownership.

Speaker B: Hospital example?

Speaker A: Put reception systems, clinical devices, guest Wi-Fi and lab equipment in one flat network. A problem in one area can have a much larger blast radius.

Speaker B: Separate subnets can make the boundaries explicit.

Speaker A: Yes. Then routing and access rules can control how those segments communicate.

Speaker B: Prediction.

Speaker B: Yes.

Speaker A: Under /26?

Speaker B: No. .10 is in the .0 block; .200 is in the .192 block.

Speaker A: Good.

Speaker B: Same addresses, different boundary.

Speaker A: Exactly.

Speaker B: And that changes which traffic is local versus routed.

Speaker A: Good. That connection matters for the next lesson.

Speaker B: Because D1.6 is routing.

Speaker A: Right.

Speaker B: So CIDR is already affecting route decisions.

Speaker A: Yes.

Speaker B: Let's make the evidence part explicit.

Speaker B: Then I verify it with a calculator or system tool.

Speaker A: Correct.

Speaker B: But only after doing the reasoning myself.

Speaker A: Exactly. The tool checks the model; it does not replace the model.

Speaker B: Another prediction.

EPISODE D1.6 — Routing, Gateways and NAT

Speaker A: We know what an interface is, what an IP address is, and what a subnet boundary is.

Speaker B: Now we need to answer the next question.

Speaker A: Where should this packet go?

Speaker B: Routing.

Speaker A: Exactly. And the visual for this lesson is:

Speaker B: Destination -> Route -> Next hop -> Boundary -> Evidence.

Speaker A: Keep that sequence in your head. It will stop routing from feeling like a list of commands.

Speaker B: Make a prediction.

Speaker A: A destination is on the local subnet. Should the host normally send the packet to the default gateway?

Speaker B: Stage one: destination.

Speaker B: IPv4 or IPv6 address.

Speaker A: Yes. The host asks: which route applies to this destination?

Speaker A: The routing table contains destinations, prefixes and often a next hop or interface choice.

Speaker B: So the host compares the destination against those entries.

Speaker A: Exactly.

Speaker B: And if several routes match?

Speaker B: Which means a narrow route can override a broad default route.

Speaker A: Correct.

Speaker B: Give me a real example.
