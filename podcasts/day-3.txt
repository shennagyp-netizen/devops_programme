EPISODE D3.1 — Kubernetes Mental Model

Speaker A: We will build the operational mental model, not memorize vocabulary.

Speaker B: I already understand application development. What changes when I operate the system?

Speaker A: Kubernetes is reconciliation: desired state, controllers, pods, workloads, services, ingress, health and resources.

Speaker B: What must I be able to do afterward?

Speaker A: Explain the causal sequence, predict failure symptoms, operate, break, diagnose from evidence, repair, and transfer the idea to production.

Hands-on: Use the Mac to run an experiment related to Kubernetes Mental Model. Make one controlled change, predict the outcome, execute it, observe the evidence, and explain the result.

Production: Place Kubernetes Mental Model in a system serving millions of users. Identify dependencies, failure domain, first useful signal, mitigation and recovery.

Recall: 1) explain without notes; 2) lowest layer that can explain failure; 3) evidence distinguishing configuration from network failure; 4) first production signal; 5) safe recovery.
