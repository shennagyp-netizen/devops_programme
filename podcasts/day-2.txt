EPISODE D2.1 — TCP and UDP

Speaker A: We build an operational mental model, not a vocabulary list.

Speaker B: I understand application development. What changes when I operate the system?

Speaker A: Build networking from the link layer upward. Keep frame, MAC, IP, route, port, socket, DNS, TCP, TLS and HTTP distinct. A failure at each layer produces a different symptom.

Speaker B: Give me the failure-oriented version.

Speaker A: State the normal causal path. Then ask what evidence appears when each dependency fails. Identify the layer, inputs, outputs, and next dependency.

Hands-on: Use the Mac to perform an experiment related to TCP and UDP. Predict the result before running it, execute it, capture the evidence, and explain the difference between hypothesis and reality.

Production: Place TCP and UDP in a system serving millions of users. Identify dependencies, failure domain, first useful signal, mitigation, recovery, and what automation should do before a human intervenes.

Recall: 1) explain without notes; 2) draw the causal flow; 3) give two failure modes and their symptoms; 4) name the first diagnostic evidence; 5) explain how scale changes the problem.
